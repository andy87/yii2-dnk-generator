## Description

Legend: 
* S_P&M > == set `property` & `methods` in to
* Env:`all` == all environment ( common/console/backend/frontend )
* Env:`backend` == environment `backend`
* Env:`frontend` == environment `frontend`

## Usage/Examples.

<a name="command-setup"></a>
### command  

```bash
php yii dnk/setup `bool`
```

| Parameter    | Type   | Description                                            |
|:-------------|:-------|:-------------------------------------------------------|
| `overwrite`  | `bool` | **optional**. overwrite exists file. defaulkt: `false` |

#### description

Generate files:
* `common/components/Entity.php` - service parts with labels
* `common/components/db/Setup.php` - Data base config: CHARACTER, COLLATE, ENGINE
* `common/components/db/Tables.php` - class with table names used Part::CONSTANT_NAME
* `common/components/resources/GridViewResource.php` - GridView Resources ( search, dataProvider )
* `backend/components/controllers/BackendController.php` - Base backend controller with common methods
* `frontend/components/controllers/FrontendController.php` - Base frontend controller with common methods
* `common/components/resources/crud/CreateResource.php` - common resource for view create
* `common/components/resources/crud/ListResource.php` - common resource for view list(index)
* `common/components/resources/crud/ReadResource.php` - common resource for view read(view)
* `common/components/resources/crud/UpdateResource.php` - common resource for view update

### command  

```bash

```

| Parameter | Type     | Description   |
|:----------| :------- |:--------------|
| `entity`  | `string` | **Required**. model/table to work with </br> * for use list fron property `parts` |

Generate gii `model` for select table(part).

Configure Gii's `--interactive` and `--overwrite` options in `command`; these
are not positional arguments of `dnk/gii-model`. A failed child command stops
the batch and its nonzero exit code is returned by DNK.

\* - generate list from config `parts`

#### Examples

```bash
php yii dnk/gii-model user
```


### Public frontend JSON fields

Inherited `FrontendController::actionList()` and `actionRead()` accept `type=json`.
Their items expose only `id` by default. Explicitly approve additional public
fields in the application controller:

```php
public const JSON_FIELDS = ['id', 'name'];
```

The list also respects the model's `fields()` definitions. An empty `JSON_FIELDS`
returns no item attributes. Keep passwords, authentication keys and internal
fields out of this list; newly added database columns are not exposed automatically.
The response envelopes remain `items`/`totalCount` and `item`.

Generated searches query the item model of their own application side through
the `MODEL` constant. Conditions configured in that model's `find()` method are
preserved by both search filters and `BaseService::findWhere()`, which adds its
criteria with `andWhere()`. This also applies when the criteria array is empty.

## Resource Profit  


```
example:
frontend/resources/user/UsereViewProfileResources {
   public const TEMPLATE = 'user-view-profile';
   
   pub string $display_name;
   pub string $age;
   
   __construct($user) {
      $this->display_name = $user->name;
      $this->age = $user->age;
      // ... other code
   }
}

frontend/controllers/UserController {
   action viewProfile(int $id) {
      $user = new (UserService())->findByID($id);
      $R = new UsereViewProfileResources($user);
      
      return $R->content();
   }
}

frontend/controllers/api/v1/UserController {
   action viewProfile(int $id) {
      $user = new (UserService())->findByID($id);
      $R = new UsereViewProfileResources($user);
      
      return $R->json();
```

## Yii2 setups  

### Install.

<a name="setup-composer"></a>
1. exec command 
```bash
composer require andy87/yii2-dnk-generator:dev-master
#OR
php composer.local require andy87/yii2-dnk-generator:dev-master
```

<a name="setup-config"></a>
2. Update config file:
- advanced: `@console\config\main.php`

```php
//.. other code

return [
    // .. other config
    
    'controllerMap' => [
        // .. other config
        
        'dnk' => [  // new block
            'class'     => andy87\dnk\GenerateController::class
        ]
        
    ]
]
```


* `root` - directory with folders 'frontend',backend',common' ...  
* `command` - part of gii/... command  
* `parts` - table lis. for user *  in command property  
* `baseClasses` - list of based class names for generated file

3. exec command [dnk/setup](#command-setup)

   The generator supplies default base classes for Yii Advanced. `baseClasses`
   is optional; individual entries can be overridden without repeating the rest.
   Empty or malformed class names are rejected before files are written.
    
4. Update `config` for you require, by example: 
   
```php

use common\components\db\Tables;
use common\components\core\BaseModel;
use andy87\dnk\GenerateController;
use andy87\dnk\source\base\BaseController;
use andy87\dnk\source\base\BaseMigration;
use andy87\dnk\source\base\BaseResource;
use andy87\dnk\source\base\BaseService;

//.. other code

return [
    // .. other config

    'controllerMap' => [
        // .. other config
        
        'dnk' => [  // new block
            'class'     => GenerateController::class,
            'command'   => [
                GenerateController::COMMAND_MODEL => implode(' ', [
                    '--modelClass={{CamelCase}}Source',
                    '--ns=' . escapeshellarg('common\\models\\sources'),
                    '--tableName={{snake_case}}',
                    '--baseClass=' . escapeshellarg('{{BaseModelClassName}}'),
                    '--interactive=0',
                    '--overwrite=1'
                ]),
                GenerateController::COMMAND_CRUD => implode(' ', [
                    '--modelClass=' . escapeshellarg('backend\\models\\items\\{{CamelCase}}'),
                    '--controllerClass=' . escapeshellarg('backend\\controllers\\{{CamelCase}}CrudController'),
                    '--baseControllerClass=' . escapeshellarg('yii\\web\\Controller'),
                    '--viewPath=' . escapeshellarg('@backend/views/{{kebab-case}}-crud'),
                    '--enableI18N=1',
                    '--interactive=0',
                    '--overwrite=0'
                ])
            ],
            'entityList' => array_values(Tables::NAMES),
            'baseClasses' => [
                GenerateController::BASE_MIGRATE_CLASS => BaseMigration::class, // extends for `Migrations`
                GenerateController::BASE_CONTROLLER_CLASS => BaseController::class, // extends for `Controllers`
                GenerateController::BASE_MODEL_CLASS => BaseModel::class, // extends for `Source` models
                GenerateController::BASE_SERVICE_CLASS => BaseService::class, // extends for `Services`
                GenerateController::BASE_RESOURCE_CLASS => BaseResource::class, // extends for `Resources`
            ]
        ]
    ]
]
```


The model command replaces generated source models (`--overwrite=1`). Keep
custom behavior in the item/form classes. The CRUD command creates a separate
standard Gii `{{CamelCase}}CrudController` in `backend/controllers/` and preserves existing
files (`--overwrite=0`). The `{{kebab-case}}` marker matches Yii controller IDs:
`user_profile` produces views in `backend/views/user-profile-crud/`. Its base
is `yii\web\Controller`: standard Gii actions
have different return signatures from DNK's controllers. Use shell-escaped
namespace arguments as shown above on both Windows and Unix. Gii must be
installed and enabled in the application's console configuration.

5. Register each additional entity in `common\components\Entity`.
   For example, the `post` entity uses a unique constant and display labels.
   Add these entries to the existing class; preserve the other entities:

```php
public const POST = 2;

public const DATA = [
    // Keep existing entries, including USER.
    self::POST => [
        self::TABLE_NAME => Tables::NAMES[self::POST],
        self::LABELS => [
            self::NAME_MANY => 'Posts',
            self::NAME_ONE => 'Post',
        ],
    ],
];
```

6. Add the table to `common\components\db\Tables::NAMES` before running
   migrations or opening the generated pages:

```php
public const NAMES = [
    // Keep existing entries.
    Entity::POST => 'post',
];
```

When display labels are omitted, pages and migration comments use the registered
table name. Labels in `Entity::DATA` take precedence. An unknown entity without
either a label or a registered table raises an explicit configuration error.
